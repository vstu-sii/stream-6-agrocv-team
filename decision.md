# Решение по архитектуре диагностики листьев

## Основание решения

Ресёрч выделил SAM + Qwen3-VL как кандидата для локального решения, а оценка бюджета — Qwen3-VL-4B NF4 как основной вариант. Для первого эксперимента сегментацию отложили, чтобы проверить саму VLM. Источники: [ресёрч](research.md), [модели и бюджет](models-and-budget.md).

В lab1 один промпт `observations_first` трижды обработал одно изображение яблоневого листа. Ответы совпали и правильно выбрали паршу относительно подтверждённой пользователем метки; основное описание пятен соответствует предоставленному фото. Генерация и подготовка прогретого запроса заняли в среднем 12,91 с, загрузка модели — 95,35 с; пиковая allocated-память PyTorch — 3,32 GiB. Это подтверждает техническую работоспособность и успех на одном случае, но не общую точность. Проверена нативная Windows-среда; WSL пока остаётся целевым вариантом развёртывания. Источник: [lab1](experiments/lab1.md).

## Решение — прямые промпты

**Для MVP выбираем прямой мультимодальный запрос к локальной Qwen3-VL-4B-Instruct NF4.** Вход — фото листа, указанная пользователем культура и ограниченный список состояний. Выход — JSON с видимыми признаками, предполагаемым заболеванием, альтернативами и запросом дополнительного снимка. При недостатке данных допускается отказ от диагноза.

Причина: этот путь уже дал пригодный для интерфейса ответ без внешних сервисов и дополнительных моделей. Для одного изображения не требуется планирование действий или поиск документов. `observations_first` остаётся исходным вариантом для дальнейших тестов, а не признанным победителем: два других промпта в полученном архиве отсутствуют. Основание: [результаты и ограничения lab1](experiments/lab1.md).

Модель сохраняем в памяти между запросами; ввод, проверку JSON и ресурсные лимиты реализуем обычным кодом. Повторы нужны для эксперимента, а не для каждого пользовательского запроса. Рабочий путь: **проверка фото → Qwen → валидация ответа → результат или отказ**. Запуск: [ноутбук с кодом](experiments/lab1.ipynb). Это проектное решение на основе измерений, не уже завершённое production-приложение.

## Альтернативы и причины отказа на текущем этапе

| Альтернатива | Почему не включаем сейчас | Когда пересмотреть |
|---|---|---|
| RAG | Поиск справочных текстов сам по себе не проверяет, верно ли распознаны пятна. Для текущей задачи добавляет корпус, индексацию и контроль источников без измеренной пользы | Когда потребуются обоснования из проверенного справочника, сравнение болезней или актуальные рекомендации |
| Агент с инструментами | Последовательность действий заранее известна; автономный выбор инструментов и циклы запросов добавляют задержку и усложняют воспроизводимость | Если появится обоснованный сценарий выбора ракурсов, инструментов или нескольких источников данных |
| SAM перед Qwen | На первом крупном снимке верный класс получен без сегментации; её вклад не измерен | Если на сложном фоне, нескольких листьях или мелких симптомах кроп стабильно улучшает качество |
| YOLO или отдельный классификатор | Потребуют отдельной интеграции и оценки; необходимость нового обучения пока не доказана | Если Qwen не выдерживает требования к качеству, скорости или локализации; существующую YOLO сохранить как кандидат для сравнения |
| LoRA/QLoRA | Один успешный пример не выявляет устойчивых ошибок и не обосновывает обучение | После формирования независимого теста и анализа повторяющихся ошибок готовой модели |
| Облачные и российские API | Не соответствуют принятому требованию локального запуска только открытых SAM/Qwen | Только при изменении требований проекта |

Это причины отложить компоненты, а не доказательство их бесполезности. Основание выбора: [обзор подходов](research.md), [ресурсные ограничения](models-and-budget.md), [границы эксперимента](experiments/lab1.md).

## Цена решения

**Берём долг по проверке диагностического качества и управлению ошибками в обмен на простой локальный MVP.** Отсутствие платы за API не означает отсутствие стоимости разработки и эксплуатации.

| Принятый долг | Что потребуется сделать |
|---|---|
| Непроверенное обобщение | Собрать независимые случаи обеих культур: болезни, отсутствие видимых симптомов, похожие повреждения и плохие снимки; получить подтверждённые метки. Один лист и три повтора не заменяют тест |
| Ненадёжные объяснения и отказы | Проверять признаки по фото, обоснованность альтернатив и ложные ответы «нет симптомов». Не трактовать написанную моделью уверенность как вероятность |
| Ограниченная локализация | Пока выдаём словесные области без точных масок и процента поражения. Если это станет требованием — отдельно вводим и проверяем сегментацию |
| Зависимость от промпта и списка классов | Версионировать шаблон, таксономию и схему JSON; сравнить три варианта. Исправление порядка полей «сначала признаки» считать новым экспериментом |
| Локальная эксплуатация | Поддерживать версии библиотек, веса, память, ошибки CUDA и офлайн-установку; отдельно проверить WSL. Учитывать время загрузки и не считать память PyTorch полной занятостью GPU |
| Будущая адаптация | При недостаточном качестве оплачивать подготовку данных, экспертизу и эксперименты LoRA либо замену модели; заранее сохранить единый интерфейс входа и результата |

## Условие продолжения

Продолжаем с прямыми промптами и проверяем их на расширенном наборе. Если хороший крупный план не устраняет путаницу заболеваний — исследуем дообучение или специализированную модель. Если проблема в выделении объекта — сравниваем полный кадр, ручной кроп и SAM-кроп. RAG добавляем для справочной поддержки, агента — только под новую задачу, требующую выбора действий. Основание: [план следующего опыта](experiments/lab1.md).
