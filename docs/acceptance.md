# Продуктовые критерии приёмки

Критерии описывают ожидаемое поведение. Приложение, модель и результаты измерений в этом пакете не представлены.

## 1. Охват и классы

Веб-приложение принимает снимок одного листа яблони через браузер; сервер в Docker обрабатывает его моделью Qwen3-VL-4B-Instruct. Результат относится к снимку, а не к здоровью дерева целиком.

| `class_id` | Текст карточки | Категория данных |
| --- | --- | --- |
| `healthy` | Без видимых признаков поддерживаемых болезней | `Apple___healthy` |
| `apple_scab` | Предположительно парша яблони | `Apple___Apple_scab` |
| `black_rot` | Предположительно Black rot / чёрная гниль | `Apple___Black_rot` |
| `cedar_apple_rust` | Предположительно ржавчина типа Cedar apple rust | `Apple___Cedar_apple_rust` |

Русские названия, описания и справочные ссылки проверяются специалистом до публичного пилота. Класс Cedar apple rust не обобщается на все виды ржавчины. Другие болезни, плоды, кора и чужие культуры входят в отрицательные проверки, а не в эти четыре класса.

## 2. Вход и результат

### Требования к веб-клиенту

Приложение открывается по URL в браузере компьютера или телефона без установки. Основной путь — «Выбрать фото» → предпросмотр → «Заменить фото» / «Проверить». На совместимых телефонах системный выбор файла может предложить камеру; недоступность камеры не блокирует загрузку готового снимка. Отмена выбора не отправляет запрос. При перезагрузке или закрытии вкладки история разбора не восстанавливается.

API принимает JPEG/PNG. Неподдерживаемый формат, включая HEIC, отклоняется с просьбой выбрать JPEG/PNG; автоматическая конвертация браузером не предполагается. Предобработка на сервере учитывает ориентацию. Интерфейс работает на узком экране и не подставляет старый ответ к новому фото.

### Требования к снимку

- JPEG или PNG, проверка по содержимому; не только имени файла или заголовку клиента.
- Максимум 10 485 760 байт (10 МиБ; в интерфейсе допустима подпись «10 МБ»).
- Максимум 24 000 000 пикселей после декодирования. Числовой предел — проектное ограничение ресурсов, проверяется Delivery и AI Engineer.
- Повреждённые файлы, несовпадение формата, слишком большой файл или изображение отклоняются до запуска модели.
- Предобработка учитывает ориентацию снимка и требования выбранной модели. Метаданные EXIF не передаются в телеметрию.

### Требования к ответу для AI-API

Это продуктовая форма результата для согласования с AI Engineer, не готовый OpenAPI-контракт.

| Поле | Требование |
| --- | --- |
| `request_id` | Корреляция запроса и ответа; присутствует и при ошибке |
| `session_id` | Объединяет попытки одного случая; идентификатор сам по себе не даёт доступа к чужим данным |
| `assessment_id` | Идентификатор попытки; может отсутствовать при отклонении запроса до её создания |
| `status` | Только `assessed`, `cannot_assess` или `error` |
| `class_id` | Один из четырёх классов при `assessed`; иначе `null` |
| `reason_code` | Причина отказа/ошибки; `null` при нормальном результате |
| `message` | Понятное русскоязычное сообщение |
| `next_step` | Обязателен при результате/отказе; при ошибке объясняет возможность повтора |
| `reference_url` | Проверенный справочный источник для карточки класса; не выдуманная моделью ссылка |
| `model_version` | Версия реально использованной модели; `null`, если модель не запускалась |

`cannot_assess` — состояние результата, а не пятый класс. При невалидном выходе модели `model_version` может быть известна, но класс не показывается. Сгенерированное Qwen число уверенности не является калиброванной вероятностью. Его нельзя использовать для порога `low_confidence` без отдельно проверенной методики. Выход модели проверяется по JSON-схеме и перечислению классов; свободный текст не отображается как диагноз или рекомендация. Подробности — [использование модели](model-usage.md).

Причины до распознавания: `file_required`, `unsupported_file_type`, `file_too_large`, `invalid_image`, `image_too_large`.
Причины отказа: `image_quality`, `unsupported_input`, `low_confidence`.
Технические причины: `processing_timeout`, `service_unavailable`, `invalid_model_output`.

Сетевой сбой может не дать ответа API: интерфейс показывает локальную ошибку и не генерирует результат самостоятельно. HTTP-коды, схемы, ограничения частоты и транспортный формат определяются в контракте AI Engineer; они должны сохранять указанные различия состояний.

### Измерение качества и ограничений

Для первого исследования: минимум 60 независимых бытовых фото, минимум 15 на класс; отдельный набор отрицательных случаев. Это нижняя граница планирования, не гарантия статистической устойчивости. Quality определяет достаточный объём по разбросу результатов и сообщает неопределённость; при недостатке данных качество считается не измеренным.

Отказы на известных классах дают пропуски правильной метки и снижают полноту; их нельзя исключать из отчёта Macro-F1. Также сообщаются доля отказов, покрытие и ложное принятие отрицательных примеров. Нельзя улучшать цифру, оставляя только уверенные ответы.

Train/validation/test разделяются по листу, растению и происхождению, насколько позволяют данные; дубли удаляются до разбиения. Метод отказа, промпт и при наличии обоснованной оценки уверенности её порог выбираются по validation-набору. Существующая модель оценивается до решения о дообучении. Целевые 0,80 не выдаются за baseline или готовый порог CI: рабочие пороги регрессии фиксируются после первого измерения.

Для p95 сортируем измерения серверной обработки и берём элемент `ceil(0.95 × N)`. Загрузка по сети и время до полного показа пользователю измеряются отдельно; таймауты/ошибки публикуются рядом с задержками, не исчезают из отчёта. Стоимость включает простой инфраструктуры и ошибки; дообучение и труд команды учитываются отдельно. При нуле запросов цена запроса не определена.

## 4. North Star

Цель из первой лабы: не менее 80% успешных первичных разборов на пилоте минимум из 30 сессий минимум пяти представителей сегмента; не более шести случаев от одного человека.

`NS = успешные разборы / все начатые оцениваемые разборы × 100%`.

Успех требует одновременно совпадения класса с независимой эталонной меткой, верного пересказа ограничения/следующего шага и положительной оценки полезности. Одного нажатия «Да» недостаточно. Эталон не создаётся проверяемой моделью.

Начало — первая отправка снимка; завершение — показ результата либо пять минут без результата. Пересъёмки того же листа, сделанные в рамках этого пятиминутного эпизода, объединяются. При закрытии вкладки и новом разборе исследователь отдельно проверяет, не повторяется ли тот же случай в пилоте. Ошибки, отказы и отсутствие оценки после начала остаются в знаменателе. Неопределённые эталоны не добавляют успехов и показываются отдельно; при отсутствии пригодных эталонов NS не измерена.

Проверки чужих культур и учебные прогоны команды маркируются заранее и учитываются отдельно. Технический `session_id` помогает связать попытки, но не заменяет исследовательский контроль независимых случаев.

## 5. Границы человеческой ответственности

Владелец принимает дальнейшее решение, специалист проверяет сложные случаи, Quality подтверждает эталоны. Модель не назначает лечение, не утверждает безопасность урожая и не формирует окончательный диагноз.
