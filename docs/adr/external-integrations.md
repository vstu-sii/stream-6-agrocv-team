# Внешние системы подключаем через адаптеры

**Статус:** Принято
**Дата:** 2026-10-22
**Роль:** Delivery
**Схема:** [C4 контейнеров](../architecture/c4-container.puml)

## Контекст

Система зависит от двух внешних источников: модельный провайдер (VLM/LLM по
API) и справочник препаратов (нормы дозировок и сроки ожидания). Оба
меняют форматы ответа, умеют отдавать 5xx и меняют лимиты. Если вызывать их
напрямую из кода пайплайна, то формат внешнего API размазывается по
приложению, а смена провайдера становится правкой во многих местах.

Варианты:

- **прямые вызовы внешних API из воркера**;
- **адаптер на каждую внешнюю систему** — выбрано;
- **универсальный шлюз ко всем внешним системам**.

## Решение

### Схема

```
ai_worker → llm_acl ($tags="acl") → модельный провайдер
ai_worker → drug_acl ($tags="acl") → справочник препаратов
```

### Обоснование

- Адаптер переводит чужой формат в наш контракт и прячет детали провайдера:
  ретраи, лимиты, разбор ошибок, названия полей.
- Наш контракт описан один раз (`api/openapi.yaml`) и не зависит от того,
  кто именно отвечает на запрос.
- Правило назначения лечения остаётся проверяемым: адаптер справочника
  отдаёт нормализованный список препаратов с дозировкой и сроком ожидания.

## Цена решения

Берём на себя: два лишних слоя кода, которые надо поддерживать и тестировать;
дублирование части логики у внешних систем; риск «просачивания» деталей
провайдера в контракт, если адаптер написан небрежно; универсальный шлюз
отвергли сознательно — он проще, но смешивает две системы с разной
семантикой в одной абстракции.

## Последствия

- Смена модельного провайдера — это новая реализация интерфейса адаптера,
  а не правка пайплайна.
- У адаптеров будут свои таймауты и ретраи — их задаёт Delivery, бюджет
  запросов — роль AI.
- Внешние вызовы идут через API Gateway: в технологии ребра указано
  `HTTPS via API Gateway`.

## Как покрыть тестами

- Контрактные тесты адаптера на сохранённых ответах провайдера (зона роли
  Quality).
- Проверка деградации: при недоступности провайдера диагностика не падает,
  а отдаёт понятный статус.

## Чем это проверяется машиной

Правило `acl` в `aact.config.ts`: во внешние системы ходят только
контейнеры с тегом `acl`; правило `apiGateway` — внешние REST-вызовы идут
через API Gateway.
