# Веб-приложение и развёртывание в Docker

## Пользовательский путь

Владелец открывает URL в браузере компьютера или телефона, выбирает фото одного листа яблони, проверяет предпросмотр и отправляет его на анализ. На совместимом телефоне системный выбор файла может предложить камеру; отдельная установка приложения не требуется. Ответ, пересъёмка и отзыв доступны на той же странице. В браузер не передаются веса Qwen.

## Серверный контур

Проектная схема: браузер → HTTP(S) → приложение в Docker (веб-интерфейс + API + внутренний модуль Qwen3-VL-4B-Instruct) → хранилище метаданных. Compose описывает запуск приложения и необходимых зависимостей. Docker-контейнер не равен отдельному C4-контейнеру: внутренний модуль модели остаётся частью серверного приложения.

- Веб-интерфейс отдаётся сервером приложения; отдельный контейнер со статикой/прокси допустим по решению Delivery, без изменения UC.
- Версии образов, зависимостей, revision весов и процессора, промпт и параметры генерации фиксируются. Веса подготавливаются при развёртывании; пользовательский запрос не скачивает новую модель.
- Хранилище метаданных сохраняет состояние после пересоздания приложения: постоянный Docker volume либо отдельная БД с постоянным хранилищем. Движок и миграции определяет Delivery. Внешний доступ к БД не требуется.
- Временные оригиналы фото не записываются в постоянные тома, образы и логи. Они удаляются после обработки; страховочная очистка — не позднее пяти минут после завершения/прерывания. Метаданные хранятся до 30 дней, сессия разбора — пять минут.
- Лимиты запросов на всех уровнях должны пропускать допустимый файл до 10 МиБ с учётом накладных расходов транспорта. До запуска модели API проверяет не более 24 Мп после декодирования.
- Готовность сервиса учитывает загрузку Qwen и доступ к хранилищу. Во время запуска и при недоступности модели интерфейс не показывает фиктивный диагноз. GPU/CPU, память, квантование и допустимая нагрузка определяются замерами AI Engineer и Delivery; наличие Docker не обеспечивает эти ресурсы автоматически.
- Публичный доступ идёт по HTTPS. Конфигурация окружения отделена от образа; секреты, токены доступа, пользовательские фото и каталог весов не включаются в PR.

## Проверка развёртывания

Delivery предоставляет Dockerfile, Compose-файл и инструкцию фактического запуска из корня командного репозитория, список переменных с примером без секретов, требования к ресурсам и загрузке фиксированной версии весов. Для лабы 2 допустим проектный контур с заглушками; для лабы 3 требуется реальная модель в сквозном пути.

Проверка AC-18: развернуть чистое окружение по инструкции, дождаться готовности, открыть страницу в браузере, выполнить UC-01/02/03, проверить перезапуск приложения, сохранность метаданных и очистку исходных снимков. Зафиксировать commit, версии образов и модели, команды и результаты. Проверки ответов заглушек отделяются от реального инференса.

Этот документ — требования PRODUCT к развёртыванию. Исполняемые Dockerfile/Compose и доказательства запуска в данном продуктовом пакете отсутствуют; успешный запуск не заявляется.
