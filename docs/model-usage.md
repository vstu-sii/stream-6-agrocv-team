# Использование Qwen3-VL-4B

## Модель и размещение

Базовый вариант: [Qwen/Qwen3-VL-4B-Instruct](https://huggingface.co/Qwen/Qwen3-VL-4B-Instruct), существующая мультимодальная модель с лицензией Apache-2.0. Веб-приложение получает снимок через браузер, API запускает модель на сервере. Вариант Instruct выбран для ограниченного ответа по инструкции. Запуск весов на телефоне и offline-распознавание не входят в MVP.

Обучение с нуля не выполняется. Дообучение на открытых данных возможно после baseline, проверки лицензий, разметки и отделения тестовых данных. Наличие модели не доказывает качество на листьях яблони. Revision весов, процессора, библиотек, квантование и аппаратная конфигурация фиксируются в фактическом AI-пайплайне; здесь результаты запуска не заявляются.

## Путь обработки

1. Веб-клиент получает файл из системного выбора и показывает предпросмотр. При доступности устройства можно сделать снимок камерой. API принимает JPEG/PNG; автоматическое преобразование HEIC не предполагается.
2. API в Docker проверяет формат, размер, целостность и ориентацию, связывает запрос с попыткой и сессией.
3. Процессор модели подготавливает изображение и версионированный промпт. Генерация ограничена по длине и времени; конкретные значения определяет AI Engineer по baseline, в рамках таймаута 20 секунд.
4. Промпт требует один JSON-объект: status, class_id, reason_code. Допустимы assessed с одним классом healthy, apple_scab, black_rot, cedar_apple_rust либо cannot_assess с null-классом и причиной image_quality или unsupported_input. Неопределённость и неизвестная болезнь не должны принудительно превращаться в один из четырёх классов.
5. Сервер проверяет JSON и сочетания полей. Посторонний текст, неизвестное значение, несовместимое состояние и усечённая генерация дают error / invalid_model_output без диагноза. Запрос JSON в промпте сам по себе не гарантирует соблюдение схемы.
6. Название, ограничения, следующий шаг и ссылка выбираются из проверенных карточек приложения. Свободный ответ Qwen не используется как инструкция по лечению.

## Отказы и измерения

Число «уверенности», придуманное моделью, не является вероятностью правильного диагноза. Причина low_confidence включается только после независимой проверки метода оценки уверенности и порога на validation-наборе. Пока такого метода нет, применяются явные отказы модели и проверки входа/выхода. Эти механизмы не гарантируют обнаружение всех чужих культур и болезней.

При измерениях фиксируются версия весов, процессора и промпта, параметры генерации, длительность, состояние и количество входных/выходных токенов. Исходные фото и полные пользовательские запросы не сохраняются в трассах; телеметрия не содержит оригиналов фото, EXIF или токенов доступа. Проверяются ошибки классов, доля отказов и ложное принятие отрицательных примеров. Цели качества, времени и цены и методы проверки заданы в [acceptance.md](acceptance.md); фактических замеров здесь нет.
