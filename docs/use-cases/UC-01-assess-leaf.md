# UC-01. Получить предварительный результат по листу яблони

**Актёр:** Владелец яблони.
**Цель:** получить возможное объяснение изменений листа и понять следующий шаг.
**Контекст:** человек заметил необычный лист своей яблони; нужна первичная ориентация, а не назначение лечения.
**Предусловия:** открыта страница веб-приложения, доступен снимок одного листа яблони, есть соединение с сервисом. Аккаунт не требуется.
**Триггер:** человек решает проверить снимок листа.

## Основной сценарий

1. Владелец читает: «Анализируем только листья яблони. Результат предварительный» и краткую инструкцию по съёмке.
2. Нажимает «Выбрать фото» и загружает снимок одного листа. Видит предпросмотр и действия «Заменить фото» / «Проверить». На совместимом телефоне системный выбор файла может предложить съёмку камерой.
3. Отправляет фото на анализ. Приложение показывает состояние обработки и не создаёт повторный запрос от повторного нажатия.
4. Сервер в Docker проверяет файл и изображение, учитывает ориентацию и передаёт изображение Qwen3-VL-4B-Instruct с фиксированным промптом и проверяет JSON и допустимость класса.
5. Показывает карточку с названием одного из четырёх классов, ограничением достоверности и следующим шагом со справочным источником. Пользовательское сообщение не содержит рецептур препаратов.
6. Владелец читает карточку и решает, нужна ли дополнительная проверка. Медициноподобное заключение о здоровье всего дерева не формируется.

## Альтернативы и исключения

- **2а. Файл не выбран или выбор отменён:** отправка недоступна; сообщение «Выберите фото листа яблони».
- **2в. Камера не предлагается устройством или доступ запрещён:** можно загрузить готовое фото; камера не обязательна для веб-сценария.
- **2б. Не JPEG/PNG, больше 10 МБ, файл повреждён или изображение превышает 24 мегапикселя:** объяснение причины и предложение выбрать другой снимок JPEG/PNG; распознавание не запускается. Расширение файла не считается доказательством формата.
- **4а. Фото размыто или лист неразличим:** состояние `cannot_assess` с причиной `image_quality`, совет переснять. Способ автоматической оценки пригодности проверяет AI Engineer; одна инструкция не доказывает наличие такого фильтра.
- **4б. Чужая культура, плод, кора, вся крона или неизвестная болезнь:** если неподдерживаемость обнаружена, `cannot_assess` с причиной `unsupported_input`. Не обещаем обнаруживать все такие случаи; отдельно проверяем ложные уверенные ответы.
- **4в. Недостаточная уверенность:** `cannot_assess` с причиной `low_confidence`. Применяется только при наличии отдельно проверенного метода оценки уверенности и порога по validation-набору. Число, сгенерированное Qwen в тексте, таким методом не считается. Без него используется явный отказ модели, а не фиктивный порог.
- **4г. Неизвестный класс, отсутствующие поля, невалидный JSON или ответ вне схемы:** техническая ошибка `invalid_model_output`; класс не показывается.
- **4д. Обработка дольше 20 секунд:** понятная ошибка `processing_timeout` и возможность повторить отправку. Скрытых автоматических повторов распознавания нет.
- **3а/4е. Сеть или сервис недоступны:** ошибка с предложением повторить позже; старый ответ не выдаётся за новый. Если неизвестно, дошёл ли запрос, повтор должен сохранять ключ идемпотентности для того же файла.
- **5а. Класс `healthy`:** текст «Без видимых признаков поддерживаемых болезней», а не «Дерево здорово». Ограничения и следующий шаг остаются обязательными.
- **5б. Справочная карточка неполна или её источник не задан:** не подменять отсутствующее описание сгенерированным советом; сообщить о неполном результате. Такой ответ не проходит приёмку.

**Точки расширения:** «требуется уточнение» — [UC-02](UC-02-refine-assessment.md); «результат показан» — [UC-03](UC-03-rate-usefulness.md). Отказ `cannot_assess` также является показанным результатом; техническая ошибка — нет.

## Результат

Владелец получает предварительный результат или объяснённый отказ. У ответа есть идентификатор, версия модели и однозначное состояние. При технической ошибке диагноз отсутствует. Оригинал фото не сохраняется для истории или обучения; условия временного хранения заданы в [ADR-002](../adr/ADR-002-data-boundary.md).

Человек принимает дальнейшее решение; система не назначает лечение и не оценивает безопасность урожая.

## Как поймём, что работает

- **AC-01:** валидный ответ имеет допустимые `status` и `class_id`; при отказе/ошибке `class_id = null`.
- **AC-02:** во всех карточках есть ограничение и следующий шаг; для `healthy` не утверждается здоровье дерева.
- **AC-03:** неподходящий файл не попадает в модель; повреждённое изображение не обрушает приложение.
- **AC-04:** некорректный ответ модели и таймаут не превращаются в диагноз.
- **AC-05:** p95 серверной обработки ≤10 секунд при пяти одновременных пользователях; цель, не результат измерения.
- **AC-06:** Macro-F1 ≥0,80 на независимом наборе бытовых снимков четырёх классов; отказы на известных классах учитываются как ошибки.
- **AC-07:** стоимость обработки ≤0,50 ₽ на запрос при 1 000 запросов/месяц; расходы на возможное дообучение отдельно.

Методики и владельцы проверок — [acceptance.md](../acceptance.md). Для отрицательных примеров отдельно публикуется доля ошибочно принятых случаев; конкретный рабочий порог определяется после baseline.

## Проживаемость

Самостоятельный прогон заявлен участником проекта, владельцем яблонь. Подробный журнал по этому UC не представлен. Это самопроверка представителем сегмента; независимый прогон человеком вне команды не зафиксирован. Основание и границы проверки — [протокол](../walkthrough.md).

Веб-ввод проверяется по AC-17, развёртывание — по AC-18 в [критериях приёмки](../acceptance.md).
