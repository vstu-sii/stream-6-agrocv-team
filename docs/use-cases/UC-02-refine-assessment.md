# UC-02. Уточнить результат по новому снимку

**Актёр:** Владелец яблони.
**Цель:** получить более пригодный для оценки снимок того же листа и повторный результат.
**Контекст:** получен отказ или владелец считает, что на первом фото плохо виден лист.
**Предусловия:** доступна карточка результата UC-01, сохраняется активный контекст разбора; можно сфотографировать тот же лист повторно.
**Триггер:** владелец выбирает «Сделать другой снимок».

## Основной сценарий

1. Владелец читает причину уточнения и инструкцию: один лист крупно, фокус на листе, ровное освещение; при необходимости — другой ракурс того же листа.
2. Делает новый снимок и загружает его через «Выбрать фото» в браузере. Проверяет предпросмотр и может заменить файл до отправки.
3. Отправляет фото. Приложение создаёт новую попытку с новым `assessment_id` в той же сессии разбора.
4. Получает отдельную карточку результата. Пока новый снимок обрабатывается, старый ответ не выглядит результатом нового фото.
5. Сравнивает доступные в текущем разборе сообщения и выбирает следующий шаг. Если ответы расходятся, приложение не объявляет последний ответ более достоверным только потому, что он последний.

## Альтернативы и исключения

- **1а. Листа нет, он недоступен или сезон закончился:** владелец завершает разбор; приложение не требует обязательного продолжения.
- **2а. Выбор файла отменён или новый файл не подходит:** действует проверка формата, размера и целостности UC-01; предыдущий результат не изменяется.
- **3а. Повторное нажатие или сетевой повтор того же запроса:** тот же ключ идемпотентности не создаёт дополнительную попытку.
- **4а. Повторный отказ:** причина показана; бесконечная пересъёмка не навязывается, предлагается дополнительная проверка человеком.
- **4б. Ошибка/таймаут:** сообщить, что новая попытка не дала результата; старую карточку явно подписать как предыдущую.
- **4в. Контекст сессии истёк или вкладка закрыта:** для новой попытки требуется новый разбор. Приложение не обещает восстановление истории после закрытия вкладки.
- **5а. Классы разных попыток расходятся:** текст «Результаты снимков отличаются. Нужна дополнительная проверка»; выбор лекарства или окончательного диагноза не автоматизируется.

**Связь UML:** `extend` к UC-01, точка «требуется уточнение», условие — владелец запрашивает пересъёмку после результата или отказа. UC-01 может закончиться без этого расширения.

## Результат

Есть результат новой попытки или понятное объяснение отказа/ошибки. Попытки различаются идентификаторами, но относятся к одному пользовательскому случаю. Для North Star повторный снимок того же листа в рамках одного разбора не увеличивает знаменатель.

## Как поймём, что работает

- **AC-08:** новый снимок создаёт новую попытку той же сессии; повтор запроса с тем же ключом не создаёт дубликат.
- **AC-09:** результат сопоставлен с нужным снимком; ответ старого запроса не перекрывает новую карточку.
- **AC-10:** при ошибке или расхождении нет ложного окончательного диагноза.
- Для каждой новой попытки действуют AC-01–AC-07 из UC-01.

## Проживаемость

Самостоятельный прогон заявлен участником проекта, владельцем яблонь. Подробный журнал по этому UC не представлен. Это самопроверка представителем сегмента; независимый прогон человеком вне команды не зафиксирован. Основание и границы проверки — [протокол](../walkthrough.md).
